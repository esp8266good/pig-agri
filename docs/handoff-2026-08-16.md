### 3. ⏸ 前提變了：tracker 參數是「幀數」，但相機只有 0.3~1 fps（那三台已離線）

`inference/tracker_pool.py` 的 `max_age=300`、`lost_track_buffer=1200`、
`track_buffer=30` 都是 **update 次數**，設定時假設 10 fps（≈30 秒 / 120 秒）。
遠端相機實際 0.3~1 fps → 變成 300~1000 秒和 1200~4000 秒，一隻豬離開後殘影
軌跡會拖十幾分鐘，影響 ID 正確性進而影響活動量。

**動它等於動追蹤行為，先做完第 1 點、有乾淨數據再談。**
⚠ `reid_revive_thresh` 寧可調小不要調大（見 CLAUDE.md）。

## 環境提醒

- 服務 `pig-agri-tmux.service`（tmux 型，非 `--reload`），改 `.py` 要重啟才生效；
  改 `static/` 直接生效，重新整理瀏覽器即可。
- **不要**另開第二份 uvicorn 對同一批錄影目錄跑 ffmpeg（寫入衝突）。
- 不要讀 `.env`（權限會拒絕）；要設定值用 `GET /settings` 或
  `uv run python -c "from config import settings; ..."`。
- 測試基準：`uv run pytest -p no:cacheprovider` 應為 **380 passed, 0 failed**。
- ~~`tracking_logs_old`（22 GB 備份表）還在~~ → 2026-08-17 已 DROP，回收 22GB。
  **踩到的坑**：不能直接 `DROP ... CASCADE`——`tracking_logs_id_seq` 的擁有者還掛在
  舊表上，但它同時是現役 `tracking_logs.id` 的 default 來源，CASCADE 會把 sequence
  一起刪掉、現役表從此插不進資料。要先
  `ALTER SEQUENCE tracking_logs_id_seq OWNED BY tracking_logs.id;` 再 DROP。
